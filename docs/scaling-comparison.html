Architecture · Current vs. Industry

Why one design funnels — and the other doesn't.

The same cameras, two structures. The difference is a single rule: does the video and data pass through a central point, or does the central point only hold a map and step aside?

heavy — video & data (must NOT centralize) light — control & metadata (fine to centralize) solid line = video/DB traffic dashed line = "who owns camera X?"

The funnel. Add 20 child servers and the master is still the one toll booth: its single database pool (max 10 connections for the whole fleet), its one disk that all video lands on, and its one network card that all viewing flows through. And if the master dies, the children kill all recording — a single point of failure. This is the cluster's design, not a bug to patch.
DatabaseOne shared master DB. Every child query proxied to it.
StorageAll video streamed to the master's disk.
FailureMaster down = whole fleet stops recording.

Industry pattern split control from media

Milestone, Genetec, Nx. A light directory only holds a map of which camera lives where. Each recording server owns its cameras, its storage, and its own database. Operators stream directly from the owning server — the directory just points, then steps aside.

No funnel. Video and DB never leave the server that owns them. The operator's stream goes straight to Server 2 (step 3, not drawn through the directory — that's the point). Need more cameras? Add a server. If the directory blips, every server keeps recording — you just lose the unified view, not the footage.

What this means for us

The best part: it's a configuration change, not a rewrite.

Phase 0 · nowRun each server standalone (cluster off — the default). Removes all three funnels by construction. Handles hundreds across 2–4 servers.
Phase 1 · buildA thin directory: one login, a map of which camera is where, cross-server search. It routes; it never carries video.
Phase 2 · laterFederation + object storage for thousands. Same codebase, no core rewrite.
One honest caveat. Standalone servers give failure isolation, not high availability. "Recording never lost" still requires RAID 6/10, per-server DB backups + replication, recording redundancy, watchdogs, and synced clocks — the price of a real security product, in any architecture.
